# Native invocation accounting

General source compilation collects physical generated-Perl locations while
emitting the unchanged Perl from the same checked AST. General JavaScript emits
COP updates at the corresponding execution phases. Recovery derives those
locations from the original authoritative generated bytes. Neither route uses
S2 source line numbers, JavaScript stack traces, or current-source guesses.
Compiler and recovery implementation digests invalidate cached artifacts when
these rules change. Legacy JavaScript output and native Perl bytes are unchanged.

A loaded layer and effective physical line identify a private location. Each
active function frame retains its current location until another native statement
updates it. While conditions can therefore retain the last body statement's COP;
for conditions and steps reset to the loop header. Single-statement optimized
blocks, multiline array/hash expressions, and foreach list evaluation follow the
native emitter's distinct rules rather than a final-token heuristic.

`Context.runBoundary(callback, origin)` and `runNativeFunction(name, args, origin)`
represent explicit application `run_function` calls. Origins are trusted host
roles `top-level`, `plural`, and `ordinal`. Each explicit run resets the entry
counter and liveness timestamp; ordinary function/method dispatch does not.
Nested runs preserve active function and host frames. Host consumers must use
these boundaries for initialization, modules, page execution, and actual nested
plural/ordinal execution rather than inventing source line identifiers.

The native 150ms liveness window is literal: a passing depth check refreshes its
timestamp; a lapsed check skips depth counting without refreshing it. Explicit
reentry rearms it. Timing-dependent deep-recursion outcomes are not universally
byte-deterministic. Independent earliest outer four-second execution time and
worker wall/heap bounds remain active even when the native gate lapses. Nested
runs cannot cancel or extend the outer deadline, unlike native nested alarm
cancellation. Outermost unwind cancels the program deadline before diagnostics.

Private recursion/deadline stop identity survives nested runs. Concrete null-method,
cast, missing-class and undefined function/method errors carry a separate private
program-error brand. Explicit function runs wrap only that brand with the native
`Died in S2::run_code running <signature>:` prefix and rebrand the result.
The trusted module guard lets the coordinator classify it; no factory or guard
is exposed through the author runtime. Unknown errors,
including JavaScript stack exhaustion, remain infrastructure failures and are
never string-wrapped into an invented S2 diagnostic or partial-success response.

Run inside the devcontainer from `src/s2/target/javascript`:

```sh
/opt/dw-node24/bin/node node_modules/typescript/bin/tsc
/opt/dw-node24/bin/node --test dist/tools/invocation.test.js
/opt/dw-node24/bin/node --test dist/tools/recovery.test.js dist/tools/native-output.test.js
/opt/dw-node24/bin/node dist/tools/selftest.js
/opt/dw-node24/bin/node dist/tools/run.js
```

Fixed independent native probes are bounded to 256MiB, ten CPU seconds, fifteen
wall seconds, and one MiB of output. They compile only trusted fixture source;
recovery never executes, syntax-checks, or introspects stored generated Perl.
Tests compare actual source, recovered, and mixed-layer execution, unchanged
native bytes, statement/control locations, physical-line recursion families,
window/reset/deadline behavior, and terminal infrastructure errors. Controlled
clocks qualify mechanisms without claiming a universal live timing result.
