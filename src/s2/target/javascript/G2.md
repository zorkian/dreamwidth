# General S2 pipeline: current source and private artifacts

This is an implementation checkpoint. The existing live server still starts the
older `createAnonymousRecentService` path. The general request pipeline and
worker are not connected to that startup path, so this document does not claim
general Recent or Entry serving.

## Program selection and authority

`MysqlActivePrograms` reads the journal-owned style map, public layer aliases,
and ordered core, i18nc, layout, i18n, theme, and user layers. Syndicated
journals use a nonempty configured `DEFAULT_FEED_STYLE` before stored style
settings. Remapping and default resolution follow the selected journal and
site configuration. The parent checks journal and layer ownership, public
aliases, source records, settings, and configuration again before publication.
Only accessed authorization tables use the existing transactional read checks.

The selected layer's **latest stored S2 source** is the program input. An absent
selected source is an explicit error. Stored compiled Perl is not read for
program selection or admitted as executable input. Saving source can therefore
change what this viewer compiles before native activation; that is an accepted
source-only behavior. Snapshot fingerprints bind source bytes and all selected
identity and configuration facts. Final reread detects persistent changes, but
does not promise distributed atomicity or arbitrary ABA detection.

The private exporter calls installed `DW::SiteScheme->inheritance(default)`
under its existing no-connect guard and exports only inert selected names.
Configuration changes require re-export and restart. Request-selected schemes,
style options and installed substitution hooks remain separate unfinished
request-context work; the default anonymous scheme fact does not replace them.

## Compilation and cache

`ArtifactCompiler` compiles each selected source through the installed
Perl-written S2 compiler's JavaScript backend in a bounded, isolated setup job.
It does not execute stored style code or render through Perl. `ProgramCoordinator`
keeps at most two active compiler jobs; equal keys coalesce and cancelling the
last waiter kills the job. Artifacts are local private files outside Git and SQL.
The key binds selected source, layer and owner identity, compiler/runtime/scalar
profile, and installed producer files. Warm hits check pinned file identities;
producer and encoding boundaries verify installed bytes. Cache entries have an
authenticated payload and are rejected on mismatch or corruption. The parent
issues a private program admission; author-supplied code and hashes cannot mint
one. There is no negative cache or alternate stored-program route.

From the owning development container after the normal TypeScript emit, run:

```sh
S2_SELECTED_FIXTURE=1 /opt/dw-node24/bin/node --test dist/tools/active-program.test.js
/opt/dw-node24/bin/node --test --test-concurrency=1 \
  dist/tools/program-coordinator.test.js dist/tools/compile-active.test.js
```

The selected fixture uses disposable schemas and verifies source changes,
missing source, owner and layer selection, and final reread. The coordinator
tests verify source compilation, authenticated cache behavior, cancellation,
private admission and installed dependency invalidation. Fixed native cases
remain independent expectations for the behavior of compiled source.

## Consumer boundary

The private channel uses bounded, sequenced control frames and separate native
byte output frames. One Context and output sink span initialization, selected
data preparation and rendering. The parent checks journal privacy before
initialization, approves named public model fields, and rereads program,
selected data and touched helper witnesses before releasing output. Native
program diagnostics require the same freshness checks. Transport, cleaner and
hard process failures cannot publish unverified partial bytes.

`SelectedDataRepository` handles the public Recent window and Entry selection
without granting program authority. The general worker still needs its full
installed host/cleaner/model bindings and actual HTTP startup. The existing
live server remains runnable during cleanup and is a narrower historical slice.
It temporarily returns a bounded unsupported response for a selected journal
user layer, before reading entry text or stored compiled layer content. Stock
Recent/Entry and the existing system-theme paths remain available. This is an
interim limitation of the old server, not a permitted restriction on the
approved general source-compiled webserver. Ordinary user settings are S2
source in `s2source_inno` and still require the general source compiler and
request path; the cleanup does not wire that path into startup.
Generated artifacts stay in ignored directories; neither cache nor worker
output is a tracked source file.
