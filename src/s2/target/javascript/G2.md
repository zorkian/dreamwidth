# General active-program request pipeline

## Parent authority checkpoint

`MysqlActivePrograms` reads the journal-owned `(userid, styleid)` map and actual
configured default/public-layer aliases. Syndicated journals use nonempty
`DEFAULT_FEED_STYLE` before stored stylesys/s2_style, following
`LJ/User/Styles.pm:584-586`. Its sitefeeds aliases are resolved without style-map
remapping; unresolved roles are absent, and an entirely empty resolved map
reaches the ordinary default branch. This is journal program selection, not a
new page type. It preserves the ordered active
core/i18nc/layout/i18n/theme/user records across their owners' configured primary
clusters. No layout, theme, literal property or source catalog determines admission.

Current source is nullable compilation evidence. Saving sourceB leaves activeA in
force until actual activation replaces compiled bytes. Global `s2compiled` bytes
are raw; positive owner clusters use exact `(userid, s2lid)` `s2compiled2` records
and the native gzip path. Corrupt clustered gzip has native memGunzip-undef
semantics: retain the original-byte witness, mark decoded active content absent,
then skip an optional layer or resolve the existing critical-layer default.
A repaired record changes the fingerprint. This does not treat a corrupt
ordinary record as a permanent style exclusion. Non-system cid0 owners use the global branch. A missing
positive-cluster record never adopts an unrelated global record. Optional absent
records are witnessed and skipped; selected missing core/layout follows the
native configured default branch. Missing default aliases remain explicit facts,
not invented replacement programs.

Native style remapping excludes user, runs once before default resolution, and
is applied in memory. Native status-history/remap persistence is deliberately
absent in this read-only viewer. Public layer parent remapping is likewise a read
projection. Settings follow source property definitions and actual global,
cluster-lite, blob and multihomed storage. Only accessed authorization tables
must pass the existing InnoDB/session-read-only checks.

The snapshot brackets global identity, both-direction name mapping, move state,
property definitions/settings, public aliases and selected layer metadata around
cluster reads. It binds source absence/bytes, stored and decoded active bytes,
comptime, owner identity/cluster and configuration. `revalidate` performs an
independent whole-request reread. This detects persistent changes; it does not
claim distributed atomicity, arbitrary ABA detection or a guarantee after the
last read. Compiled/source bytes are parent-private and never an HTML model.

Source locations: `LJ/S2.pm:735-807` map/remap/default, `807-870`
ordered stack and critical fallback, `458-548` owner grouping/cluster decoding,
`612-727` public aliases/parent remap, and `990-1015` siteviews. Property storage
follows `LJ/User/Account.pm:810-877`. Native missing alias/metadata distinctions
are preserved even where the existing G1 compiler capture cannot yet consume
them; they are coordinator work, not product exclusions.

## Trusted configuration setup

Re-export private configuration after configuration changes, then restart.
The exporter calls installed `DW::SiteScheme->inheritance(default)` under sticky
DB connection tripwires and suppressed diagnostics, exporting inert names only.
Legacy private files lacking inheritance or feed-style facts need re-export
before the corresponding siteviews or syndicated selection;
the loader does not guess an inheritance chain. Its trusted setup `modify_scheme_list` callbacks may run; CSS-hook identity
inspection does not execute CSS callbacks. A swallowed connection attempt still
prevents publication. This fact describes default anonymous context: native
request note/query/cookie scheme selection remains subsequent request work.

## Phase B: private compiler and recovery coordinator

`ProgramCoordinator` prepares the ordered authoritative active stack. It first
asks the reviewed source compiler to prove exact native compdata correspondence.
Missing source, changed source and current-checker structural prerequisites select
whole-stack recovery from the original active bytes. They do not authorize latest
source execution or permanently exclude a style. Empty stacks remain represented;
initialization and native diagnostic handling belong to the next worker phase.
Both routes retain the installed Perl scalar profile and native unflagged byte
views of layer metadata.

Artifacts live in an explicitly supplied private local cache, outside Git and
SQL. The key binds selected bytes/identity, source compiler/runtime/profile and
actual installed recovery job/parser/lowerer bytes. Authenticated cache corruption
or producer mismatch regenerates; unsafe filesystem ownership, permissions,
symlinks and inode races still fail closed. Parent issuance uses private object
brands. The private worker channel will transfer its program and expected digest
identity; `program.ts` validates and brands that transfer without filesystem,
compiler, subprocess or database imports. A caller's code plus its own hashes is
not parent-channel authority. Do not expose this admission API as a public route.

Two service slots cover compilation and recovery through child close/reaping.
Different keys queue; equal keys coalesce. Cancelling one waiter preserves another
waiter, and cancelling the last waiter kills the active job without cache
publication. The coordinator has a 120-second composed service lifetime including waiting.
The optional source proof reserves at least half the remaining lifetime for active
recovery and retains its existing isolated compiler budgets (up to60 seconds).
Its own budget expiration kills/reaps only that proof, then attempts active
recovery; caller cancellation/deadline still stops the whole attempt. Recovery uses
a 60 CPU-second external limit, 60-second wall ceiling, 512MiB V8 heap and 128MiB
input/output envelopes; individual selected blobs retain MEDIUMBLOB bounds and
the compiler's 64MiB cumulative input ceiling. These are producer service/resource
bounds, not native account or style limits. Resource failure is transient; an
unimplemented recovery syntax is an unfinished compiler dependency.

The recovery job parses and lowers inert generated Perl; it never executes stored
Perl or emitted JS. Absolute util-linux `prlimit` execs the unchanged kernel
network-denying `sandbox.c`, which execs Node24 as the same PID. Only three pipes,
LANG/TZ, exact regular-file installed recovery modules/job and indispensable
package metadata are available. Node permissions deny writes, subprocesses and
addons; kernel restrictions additionally deny network and inherited descriptors.
There is no repository-root grant, source/checker/profile/cache secret or serving
configuration in this job. Parent-computed input/output and installed producer
hashes supply provenance. Cancellation/deadline kills and reaps that same Node
PID before its service slot is released.

Run inside the owning devcontainer after the normal Node24 TypeScript emit:

```sh
/opt/dw-node24/bin/node node_modules/typescript/bin/tsc
/opt/dw-node24/bin/node --test --test-concurrency=1 \
  dist/tools/program-coordinator.test.js dist/tools/compile-active.test.js
```

The compact independent native fixtures cover matching/sourceB/missing source,
metadata mismatch and byte views, authentic cache regeneration, installed adapter
and extracted-profile invalidation, two-slot/coalesced cancellation and deadline
reaping. Actual sandbox controls deny network, private files, writes, subprocesses
and extra descriptors. The existing compiler suite retains the stock59 compile
coverage and executable custom/scalar proofs. This checkpoint does not claim
actual general Recent/Entry serving: initialization-before-data, synchronous host
IPC, GB/GO output integration and final privacy reread remain mandatory G2 work.


### Reviewed coordinator availability corrections

Installed SHA identities are pinned at construction. Warm keys/restores compare
bigint device/inode/size/mtimeNs/ctimeNs and fail closed on any change, without
re-reading large executables. Producer/encode boundaries additionally rehash the
installed bytes. Identical-content inode replacement and restored-mtime edits are
still detected; a trusted reinstallation requires a new producer.

Only the reviewed adapter's explicit gap.deterministic===true is eligible for an
authenticated negative cache entry. Its layerId/reason and complete input,
compiler/runtime/profile/recovery digests are validated on restore. A repeat
encounter spawns no job; adapter change retries. RangeError, false/absent origin,
mixed transient results, cancellation and resource failures never produce a
negative. A negative means an unfinished recovery implementation, not a permanent
ordinary style exclusion. Corrupt negative authentication regenerates normally.

Noncancel optional source-proof service failures (including a real source-only
timeout) fall back to active recovery while the outer service lifetime remains.
The two-slot queue retains both child lifetimes through kill/reaping; no process
or allocation kernel limits are relaxed. An explicit caller deadline is still the
upper bound. The coordinator and source proof intentionally have separate timers,
so default source expiry cannot consume the entire default recovery opportunity.


Negative determinism covers both routes: only missing/structural/correspondence
or a returned deterministic failed source proof plus deterministic active recovery
gap can be persisted. A source service failure or proof-budget expiry followed by
a recovery gap remains uncached RecoveryIncomplete; a later unhurried matching
source proof may succeed. This includes coalesced short/long waiters sharing a
short optional-proof hint. Changing coordinator bytes invalidates older negatives.

## General consumer foundation

The private transport uses bounded length-prefixed byte frames on FD0/FD1. Control
messages carry a version, private job identity, direction-specific sequence and
explicit initialization/data/render phase. Control JSON is canonical and strictly
UTF8; final output bytes are separate binary frames. The measured unchanged
sandbox supports a blocking worker read while the parent asynchronously answers a
synchronous host request. Stdout is reserved for this protocol.

`SelectedDataRepository` separates displayed data from active-program authority.
`MysqlLiveStore.loadSelectedSnapshot` loads the requested public window (including
its lookahead) without consulting the former catalog/style tables. Its matching
recheck repeats those dependencies. The general coordinator must additionally
bind and recheck the original `ActiveProgramSnapshot` and dynamic public host
witnesses before publication. A selected snapshot alone grants no program or
publication authority. The legacy snapshot API retains its previous behavior.

The HTTP boundary accepts exact byte output for GET/HEAD and computes length from
those bytes. Legacy string output remains transitional until the general worker
is connected; it does not authorize decoding general output as UTF8.

Declared-property traversal uses the actual layer metadata, retains composite
alias identity and preserves private runtime type/null markers. System properties,
renamed properties and grouped overrides precede initialization. The pure content
`general-contexts` subpath supplies byte-preserving plain escaping and the native
CSS/CSS-attribute screening operation. Only whole CSS reaches the explicitly
supplied trusted stylesheet transform; braces short-circuit CSS attributes.
The property traversal has an explicit 100,000-node/1,000-depth resource bound.

This checkpoint is not general serving acceptance. Same-worker initialization,
actual HTML/property eval-register behavior, public dynamic hosts, selected-model
resume, general closed staging, and final combined reread remain implementation
work. The reviewed GN run/error dependency must be integrated before its consumer
wiring; no alternate error brand or runtime-boundary implementation is provided
here. Existing finite content refusal behavior is not an accepted general policy.
