# General active-program request pipeline

## Parent authority checkpoint

`MysqlActivePrograms` reads the journal-owned `(userid, styleid)` map and actual
configured default/public-layer aliases. It preserves the ordered active
core/i18nc/layout/i18n/theme/user records across their owners' configured primary
clusters. No layout, theme, literal property or source catalog determines admission.

Current source is nullable compilation evidence. Saving sourceB leaves activeA in
force until actual activation replaces compiled bytes. Global `s2compiled` bytes
are raw; positive owner clusters use exact `(userid, s2lid)` `s2compiled2` records
and the native gzip path. Non-system cid0 owners use the global branch. A missing
positive-cluster record never adopts an unrelated global record. Optional absent
records are witnessed and skipped; selected missing core/layout follows the
native configured default branch. Missing default aliases remain explicit facts,
not invented replacement programs.

Native style remapping excludes user, runs once before default resolution, and
is applied in memory. Native status-history/remap persistence is deliberately
absent in this read-only viewer. Public layer parent remapping is likewise a read
projection. Settings follow source property definitions and actual global,
cluster-lite, blob and multihomed storage. Only accessed authorization tables
must pass the existing InnoDB/session-read-only checks.

The snapshot brackets global identity, both-direction name mapping, move state,
property definitions/settings, public aliases and selected layer metadata around
cluster reads. It binds source absence/bytes, stored and decoded active bytes,
comptime, owner identity/cluster and configuration. `revalidate` performs an
independent whole-request reread. This detects persistent changes; it does not
claim distributed atomicity, arbitrary ABA detection or a guarantee after the
last read. Compiled/source bytes are parent-private and never an HTML model.

Source locations: `LJ/S2.pm:735-807` map/remap/default, `807-870`
ordered stack and critical fallback, `458-548` owner grouping/cluster decoding,
`612-727` public aliases/parent remap, and `990-1015` siteviews. Property storage
follows `LJ/User/Account.pm:810-877`. Native missing alias/metadata distinctions
are preserved even where the existing G1 compiler capture cannot yet consume
them; they are coordinator work, not product exclusions.

## Trusted configuration setup

Re-export private configuration after configuration changes, then restart.
The exporter calls installed `DW::SiteScheme->inheritance(default)` under sticky
DB connection tripwires and suppressed diagnostics, exporting inert names only.
Legacy private files lacking this fact need re-export before selecting siteviews;
the loader does not guess an inheritance chain. Its trusted setup `modify_scheme_list` callbacks may run; CSS-hook identity
inspection does not execute CSS callbacks. A swallowed connection attempt still
prevents publication. This fact describes default anonymous context: native
request note/query/cookie scheme selection remains subsequent request work.

## Proof and remaining pipeline

From `src/s2/target/javascript` in the owning development container, after normal
content/S2 locked setup and emit:

```sh
S2_SELECTED_FIXTURE=1 /opt/dw-node24/bin/node --test dist/tools/active-program.test.js
/opt/dw-node24/bin/node --test dist/tools/site-config.test.js
S2_PRIMARY_FIXTURE=1 /opt/dw-node24/bin/node --test dist/live/tests/primary.test.js
```

The compact oracle compiles trusted fixed executable custom layers with the
installed native compiler and measures actual `get_style`/`siteviews_style`.
Its offline compiler budget is 512MiB/5CPU seconds/10 wall seconds; this is not a
serving budget. Disposable three-schema SQL evidence covers owner clusters,
cid0, foreign numeric-map collisions, saved/missing source versus active bytes,
optional absence, default fallback and mutation revalidation. Fixture schemas
are removed in `finally`; ordinary records are only read for retained system
bytes. There is no actual general HTTP claim in this parent checkpoint.

Next required phases are reviewed recovery/compiler coordination and pure worker
admission, one initialization before selected data, synchronous typed host IPC,
general public helper/model behavior, GO/GB exact-byte streaming and final
privacy reread before HTTP publication. Existing compiler snapshot restrictions
must not become permanent native style exclusions; incomplete native stacks and
preparation failures need source-correct consumer handling. Installed
`substitute_s2_layers_user` and request-selected site scheme behavior remain
reached helper/context work. No latest-source fallback or finite safe-chunk
membership defines the general pipeline.

Ordinary S2 errors, including source-reported style timeout, are distinct from
protocol/transport/hard deadline and cleaner failures. Later serving must retain
native partial-output/error ordering through GB completion, encode author
diagnostics, and perform final dependency validation before releasing any
ordinary error page. External kills cannot authorize unverified partial bytes.
