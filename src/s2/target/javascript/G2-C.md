# General consumer: parent/session checkpoint

This is an intermediate implementation checkpoint, not a general-serving milestone.
It combines reviewed program/recovery, scalar/COP, stop-kind, character-profile and
initialization-output dependencies. The general subject dependency remains held;
no held subject or encoding converter implementation is included.

## Ready boundaries

`GeneralProgramSession` creates one native output sink before `prop_init` and
`modules_init`, then retains that exact Context and sink through data resume and
printing. Initialization suppresses the current printer independently of CSS
scratch. `beginRendering` rebinds the current pair without clearing saved printers,
depth or pending CSS. A native `end_css` can consequently restore the suppressed
initialization pair. An initialization error is returned through a separate trusted
encoded diagnostic path, without starting Page output or reading selected entries.

The private channel binds job, sequence and phase; it admits only named installed
public helper operations. Page bytes use canonical scalar/base64 frames, retaining
invalid UTF8 octets and the native flag. The approved-model wire retains native
numbers, hash-key identities, aliases, cycles and array holes. It rejects Context,
callbacks and accessors; it is not an approval mechanism for raw SQL fields.

`GeneralRequestPipeline` captures the request, checks journal privacy before
program initialization, prepares the actual active program, and waits for the
initialized item count before selecting SQL data. Its installed projector must
approve named public fields before model encoding. All touched public-helper
witnesses precede journal/program/selected-data rereads; the selected reread is the
last await before release. Initialization diagnostics and native partial program
errors require the same freshness checks. This detects persistent changes, not
arbitrary ABA or distributed atomicity.

The pre-init journal authority reads identity and public settings without entry or
comment tables. Deleted, suspended, purged and identity-journal Recent/Entry paths
cannot initialize a program. Email validation is not an owner read gate. The
retained private-viewer adult-content policy remains separate from program support.
The native selected-byte loader also checks these journal boundaries before
selected content reads. Original DBI octets and native corrupt-gzip undef remain
separate from subsequent source text conversion and cleaning.

Public users have primary two-direction name/ID witnesses, including absence and
identity changes. Public cleaner translations preserve source file/DB precedence
under SELECT-only reads, without fallback persistence or cache writes. Only public
`ml_*` and `codes WHERE type='encoding'` use their specific MyISAM exceptions;
private authorization dependencies retain InnoDB checks. Encoding code/item bytes,
source numeric sort, duplicate-last-wins and absence are witnessed. Owner `oldenc`
is part of native selected authority. Native conversion is a separate mandatory
dependency, not a license to interpret original octets as final helper inputs.

The general installation descriptor selects one fixed worker entry independently
of a stock catalog artifact. Stage hashes, lock, exact inventory, ownership,
static dependency checks, Node permissions and unchanged kernel sandbox remain.
The fixed site-URL client imports no parent SQL/domain implementation; parent URL
expansion is typed scalar IPC, not a navigation grant.

## Evidence boundary

The maintained tests distinguish actual installed native helpers, actual isolated
SQL, actual source/recovered Context execution, actual sandbox pipes and injected
parent orchestration controls. The general stage test uses a synthetic fixed
entry: it proves closed installation mechanics, not a production general worker.
Native helper comparisons do not claim full native page parity. Generated profiles,
compiled programs, stage roots, SQL fixtures and reports remain local evidence.

## Mandatory continuation

A concrete installed general worker and complete source-derived Page/Entry/UserLite
model and host assembly are still required. Held subject integration, general
body/metadata/comment/property contexts, installed public hooks, effective language
and source eval effects, and post-source charset transformation remain unfinished.
The encoding converter/profile must be independently reviewed before consumption.
The native request style/scheme/substitution paths also require actual consumer
wiring. Finally, fresh real-worker closure, ordinary main Recent/Entry GET/HEAD,
custom source and recovered execution, independent native comparison, browser and
persistent privacy/revocation proof remain mandatory. None of these gaps is a
permanent journal/style/content exclusion or a completed replacement claim.
