# Context typography

Historical qualification only: after the source-only cleanup, the retained
old server refuses selected journal user layers. Their settings are S2
source; the approved general server must compile that source and is not yet
wired to startup. No stored generated Perl reader remains in serving.

The private Recent/Entry viewer adds eighteen string literals: family, size and
units for `font_module_heading`, `font_module_text`, `font_journal_title`,
`font_journal_subtitle`, `font_entry_title` and `font_comment_title`. Each family
has the corresponding `_size` and `_units` properties. Existing23 literals and
the fully consumed inert compiled-wrapper boundary are unchanged. Stored
functions/expressions/unknown keys/types/trailing bytes refuse. Owner/parent,
source, compiled data and compile-time identities remain freshly rechecked.

Unchanged stock `generate_font_css` orders specific family, base family, then
fallback. Empty specific family inherits. Size emits only when both size and
units are nonempty, using their original concatenation: no numeric conversion,
invented defaults or CSS rewriting. UI `values` metadata is a hint, not compiler
enforcement. `font_fallback`, `font_base_size`, `font_base_units` and font-source
URLs remain outside this subset. EasyRead's malformed page-family omissions and
fixed1em inventory remain exact; its native body browser fallback is not repaired.

At actual inline CSS emission, the credential-free child requires family and
size proof callbacks for the new typography path. CSS Tree parses the emitted
size+unit as one value and matches its maintained `font-size` grammar. Functions,
URLs, Raw data, controls/style-end and values above1024UTF8bytes refuse. The AST
is proof only; original bytes go to unchanged stock generation. Each original
family/size scalar must also be token-closed under the maintained tokenizer:
closed and unterminated comment tokens, bad/unterminated strings and trailing
escape/EOF repair refuse. Quoted comment-looking text in a properly closed
string remains a string. This stricter fragment boundary also covers existing
`font_base` and the family proof used by EasyRead's exact omission reader. Empty size or
units do not undergo size-value proof, because native emits no size declaration.

Malformed/unprovable families and emitted sizes can refuse the whole page where
native/browser might drop one declaration. This is an explicit stricter boundary,
not native equality or a claim that every invalid numeric range is rejected.
Whitespace-only families and size/declaration injection refuse when reached.
Existing raw/serialized hook URL guards and whole-stylesheet safety still apply.
No external font requests, CSS endpoint, body CSS policy, runtime/compiler,
dependency or SQL changes are introduced. Historical no-property output remains.

## Validation

Use the ordinary full build and fresh stage setup in [SLICE-19.md](SLICE-19.md),
then run in the owning development container:

```sh
cd "$LJHOME/src/content"
PATH=/opt/dw-node24/bin:$PATH
export PATH
npm run build
node --test tests/stylesheet.test.mjs
cd ../s2/target/javascript
node node_modules/typescript/bin/tsc
export S2_LIVE_TEST_ARTIFACT=/absolute/path/to/current-stock.json
node ../../../content/tools/stage-runtime.mjs "$S2_LIVE_TEST_ARTIFACT"
S2_SELECTED_FIXTURE=1 S2_STYLES_BROWSER_OUTPUT=/tmp/slice21-browser \
  node --test dist/live/tests/styles-native.test.js dist/live/tests/styles-http.test.js
```

Independent native compact expectations cover family order, empty inheritance,
size omission and exact unsafe generated bytes. One combined wrapper reaches six
stock declaration contexts in both qualified layouts/views. Current disposable
SQL/child/HTTP checks rendered typography, hidden-comment exclusion, emitted
injection422 versus un-emitted size200, and compiled mutation409/restored200.
Chromium checks header/entry/comment/module families and sizes with only exact
local resources. This is synthetic fixture proof, not font-binary or general
native-page parity. Existing410/Entry62/no-feature and repository gates remain
separate, with fresh attestation binding current source/build.
